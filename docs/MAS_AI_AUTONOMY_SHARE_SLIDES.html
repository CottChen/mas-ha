Vocabulary

先把两个容易误解的词讲清楚

确定性门禁

不是让模型“更自觉”，而是用代码在关键出口做硬检查。比如 schema 校验、typed tool 解析、AuditPacket 对账、权限边界、HA 终验空壳 accept 拦截。模型可以判断，门禁负责阻止明显不合格的判断进入下一状态。

schema repair audit gate permission

本地只读 intake

HA 在生成合同前，对用户明确给出的 README、任务说明、数据目录、模板、配置和代码做只读理解。它的目的不是提前交付，而是把目标、边界、关键口径和验收风险定义准。

read grep find ls 只读 bash

一个负责“不能错过门”，一个负责“进门前先看清楚”。

自动压缩

会话消息超过约 18000 字符时抽取式压缩，保留最近 10 条消息，摘要约 12000 字符以内。

AionUI 中展示的思考、工具流、模型配置不会自动进入下一轮 agent 上下文。

Request Lifecycle

第三层：一次 request 如何形成闭环

1. Prompt恢复会话历史，写入 user message，处理控制命令。
2. HA 路由answer、clarify 或 execute；execute 时生成验收合同。
3. BaselineMAS 创建边界 snapshot，准备后续审计。
4. Ego执行任务，提交 ego_result。
5. Audit构造 AuditPacket，对账工具、写入、changed_files。
6. Superego只读复核，提交 accept / revise / escalate。
7. HA 终验代表用户最终 accept、revise 或人工介入。
Acceptance Contract

合同是 request 生命周期里的核心接口

合同字段

objective readonlyInputs allowedOutputs forbiddenStates keyCriteria doneCriteria requiredEvidence validators riskNotes

流转

HA 定义合同，Ego 按合同执行，MAS 用合同推断边界，Superego 按合同审计，HA 再代表用户验收。

合同不是官样文章，它决定了“完成”的含义。

Tool-MAD

理论底座三：异质工具比普通 debate 更可靠

论文核心观点

  • 普通 MAD 主要依赖模型内部知识或静态文档，容易共享幻觉。
  • Tool-MAD 给不同 agent 分配不同外部工具，例如 RAG 和 Search API。
  • 每轮根据对方论点动态改写 query，而不是只在开头检索一次。
  • Judge 使用 faithfulness 和 answer relevance 作为稳定性信号。

Heterogeneity

异质性不是“多几个 agent”，而是让错误不再强相关

异质性维度含义MAS 中的体现
角色异质不同 agent 的目标函数不同HA 守用户目标，Ego 做交付，Superego 做审计证伪。
工具异质不同 agent 的外部能力不同Ego 有写和执行；Superego 有只读审计；HA 有外部检索和终验复算。
证据异质结论来自不同证据通道用户请求、合同、AuditPacket、工具结果、外部来源、Experience Graph。
模型异质不同角色可使用不同模型AionUI 会话模型只作用于 HA；Ego/Superego 可用角色环境变量覆盖。
上下文异质每个角色只看到框架显式传入内容Pi role session in-memory 隔离；Ego 额外看自身执行摘要；展示流不自动进入上下文。
终止权异质谁能结束任务由状态机控制只有 HA 终验能真正 escalate；Ego/Superego 只能上报内部信号。

MAS 的异质性目标：跳出固定吸引子，但仍受合同、权限、审计和当前证据约束。

Freud Model

从异质系统回到单个 agent：LLM 的三个面

原始 LLM 能力

产生候选解释、直觉路径和捷径。它有创造力，也容易幻觉、偷懒、套模板。

Ego 现实执行面

把候选想法放到当前文件、数据、工具、权限和用户目标中检验，完成真实交付。

Superego 约束反思面

发现看起来完成但真实理解错了的情况，提出反事实问题和审计约束。

HA 不属于心理三面模型。HA 是组织层的人类助理，负责理解任务、定义合同和最终验收。

Context Management

协作能持续，是因为上下文显式管理

HA 可见上下文

同一 AionUI 会话摘要和最近历史、skills、当前用户请求、扰动、路由/终验阶段的本地只读证据、外部检索和近期活动工具结果。

Ego 可见上下文

当前任务、同会话历史、HA 合同、上一轮批注、Ego 自己之前执行摘要、扰动、mas_query_memory 查询结果。没有近期活动和外部检索。

Superego 可见上下文

当前任务、同会话历史、HA 合同、Ego 输出、AuditPacket、扰动、只读检查、记忆和近期活动工具结果。

压缩与存储

进入 prompt 的历史会自动压缩；原始 runs、agent_runs、audit、events 继续保留用于追溯。Pi role session 每次新建、用完 dispose。

Code vs Prompt

最后落到实现边界：代码兜底，prompt 塑形

代码负责

  • 协议、生命周期、状态机
  • 权限、工具白名单、超时
  • typed tool schema 和 repair
  • 审计包、门禁、存储、压缩

Prompt 负责

  • 身份和职责
  • 工作人格和判断倾向
  • 工具纪律
  • 证据标准和收口方式

不要让 prompt 承担状态机，也不要让代码写死所有判断。

Prompt Best Practice

Prompt 的重点是工作人格，不是补丁墙

补丁式 prompt

如果是 Excel，必须兼容 Mac。 如果是奖金包，要注意全国值。 如果是分母，要特别检查。 如果看到 output 目录，就必须写 output。

问题：过拟合历史事故，容易误触发，污染基础 prompt。

人格式 prompt

对高风险数据、表格、报表、配置迁移和接口兼容任务， 先形成实现假设清单，覆盖字段/格式约束、映射关系、 计算基准、时间范围、单位换算、缺失/异常处理和适用范围。 验证要优先证明真实能力，而不是证明文件像结果。

优势：能泛化到新任务，又不抹掉当前证据。

Superego Review

Superego prompt 的核心：找“合理但错误”

评审前四问

  • Ego 最可能在哪里被候选路径带偏？
  • 哪个用户口径错了也会看起来合理？
  • 验证是在证明文件像结果，还是口径正确？
  • 有没有低成本样本能证伪 Ego 理解？

Takeaways

研发可以带走的 10 条原则

1. 把 agent 看成组织，而不是函数调用。

2. 先设计证据流，再设计对话流。

3. 合同是用户意图到可执行任务的接口。

4. Critic 必须有不同证据，不然只是复述。

5. Prompt 要塑造人格，不要堆补丁。

6. 上下文要显式、可压缩、可追溯。

7. 结构化输出必须有 schema、repair 和 gate。

8. 审计证据必须能覆盖模型自报。

9. 外部检索是异质视角，不是权威结论。

10. 自主性要有能量预算和熵下降目标。
