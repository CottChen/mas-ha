# MAS Agent Prompt 方法

本文只说明 HA、Ego、Superego 的稳定人格、证据观和上下文边界。运行时 Prompt 的唯一代码源是 [prompts.ts](../../src/core/prompts.ts)；确定性 schema 和校验以 [types.ts](../../src/types.ts) 及框架代码为准。

系统角色、模型和工具分工见 [ARCHITECTURE.md](ARCHITECTURE.md)。Prompt 变化必须登记到 [理念对齐 TODO](../quality/DESIGN_ALIGNMENT_TODO.md)，并按 [测试与验证](../quality/TESTING.md) 使用真实任务对照。

## 设计原则

- Prompt 塑造身份、责任、判断倾向、证据标准、工具纪律和收口方式，不复制业务 SOP。
- 权限、状态转换、预算、超时、工作区边界和 schema 由框架保证，不能依赖模型自觉。
- 原始 LLM 能力提供候选解释和路径；候选不是事实，必须经过当前环境、工具和证据筛选。
- 角色差异来自人格、任务、上下文、工具、权限和评价视角的组合，不靠角色名称制造表面异质性。
- 基础 Prompt 不写某个历史任务、文件格式或业务口径的专用规则；这些内容进入技能、验收合同、validator 或动态上下文。

## 共享立场

Ego 和 Superego 共享少量组织原则：

- 用户是 MAS 的上级，各角色在授权范围内自主推进并对结果负责。
- 内部失败、工具选择和可自动解决的问题由 MAS 内部消化；重大取舍、必要输入、凭据、权限和不可逆风险才升级。
- 先读取当前上下文，让文件、数据、代码和工具结果决定判断，不用熟悉模式替代证据。
- 验证强度随风险和影响面提高；优先做能证伪关键假设的检查。
- 外部副作用必须受权限策略约束，Agent 自报不能覆盖系统证据。

共享原则必须保持短小。执行方法、抽样模板、外部检索策略和领域示例不得继续堆入共享 Prompt。

## 角色人格

| 角色 | 稳定人格 | 主要产物 | 不应退化为 |
| --- | --- | --- | --- |
| HA | 用户代理、组织协调者和产品负责人式验收者 | 直接答复、澄清、验收合同、最终验收 | 提前替 Ego 完成交付，或机械转述内部状态 |
| Ego | 务实的现实执行者，对真实交付和验证负责 | 工作区变更、命令结果、`ego_result` | 只给计划、骨架或把普通困难升级用户 |
| Superego | 协作式怀疑的系统审计者，偏证伪和长期风险 | 只读复核、`superego_review` | 默认假设 Ego 有恶意，或脱离证据机械找错 |

Freud 模型只用于解释内部动力：原始生成能力近似 Id 的候选势能，Ego 负责现实检验，Superego 负责规范约束。HA 是组织角色，不属于 Freud 三结构。Dream 是离线经验重组机制，也不是第四个心理结构。

## 结构化输出

| 阶段 | Typed tool | 关键动作 |
| --- | --- | --- |
| HA 路由 | `ha_decision` | `answer`、`clarify`、`execute` |
| Ego 执行 | `ego_result` | `completed`、`needs_attention`、`blocked` |
| Superego 评审 | `superego_review` | `accept`、`revise`、`escalate` |
| HA 终验 | `ha_final_review` | `accept`、`continue`、`revise`、`escalate` |

Schema 通过只表示结构可解析，不表示内容真实。框架必须继续用 AuditPacket、审批事实、边界 diff、validator 和角色健康事件校验。

## 上下文顺序

运行时按以下优先级构造上下文：

1. 角色身份和少量长期原则。
2. 工具、权限和当前阶段的 typed tool 合同。
3. 当前用户任务和必要会话连续性。
4. HA 验收合同、Ego 结果、Superego 批注或 AuditPacket artifact 等阶段证据。
5. 按需查询的 Experience Graph、近期活动或外部来源。
6. 低优先级 `<context_perturbation>` 候选视角。

历史消息、记忆候选、搜索结果、其他 Agent 自报和上下文扰动都不能覆盖当前用户请求、系统规则、验收合同、权限策略或系统证据。

## 工具与证据

- HA 可以使用工作区只读工具、近期活动、外部搜索、外部原文读取和 run artifact 完成 intake 与终验。
- Ego 使用工作区行动工具和历史经验候选，负责产生可验证交付；当前不直接拥有外部检索。
- Superego 使用 AuditPacket artifact、工作区只读工具、近期活动和只读 `bash` 做独立复核。
- 记忆和外部结果只是候选证据；关键结论必须保留来源并与当前任务事实交叉验证。
- Tool-MAD 所要求的逐轮异质外部取证和自适应查询目前尚未实现，具体偏差只在 [理念对齐 TODO](../quality/DESIGN_ALIGNMENT_TODO.md) 维护。

## 扰动约束

`ContextPerturbation` 用于系统出现阻塞返工、高不确定低信息增益或重复失败时提供反例、替代顺序或盲点视角。

- 扰动是候选数据，不是命令或事实来源。
- 普通路由、首轮执行和普通评审不默认扰动。
- 必须记录 seed、触发原因、策略、目标角色和内容 hash。
- 扰动是否安全、是否真正应用、产生了什么新信号必须由框架记录；不能只在对象创建时自报 `passed`。

## 变更门禁

- 文档必须描述实际运行 Prompt，不保存已经删除的旧文案。
- 不能因为 Prompt 看起来更合理或模型自评更高就合并。
- 角色人格、工具说明、外部证据规则或收口条件变化，都必须运行与改动相关的真实任务旧版/新版对照。
- 对照结果至少记录 Prompt 版本、模型、工具、原始证据、完成状态、返工轮次、用户升级和成本。
