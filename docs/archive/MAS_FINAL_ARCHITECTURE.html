MAS 最终系统架构

低熵自主改进是底座，Goal 是人类控制面

MAS 不需要用户设置 Goal 才能持续改进。每次任务执行都会产出证据、审计、经验和改进候选；Goal 只在用户希望控制长期方向、预算、暂停/恢复和验收时附加到这条默认闭环上。

默认持续改进

run 后证据自动进入 Experience Graph、Reflection、Dream 和 Consolidation。

Goal 不等于自主性

Goal 只是方向盘、刹车、预算和验收面板，不是系统能力开关。

证据优先

AuditPacket、验证结果、用户反馈和脱敏样本优先于模型自报。

一、最终架构总览

入口与编排
AionUI / CLI

用户任务、slash command、权限请求和状态展示入口。

ACP Server

只做协议转换、会话生命周期、展示映射和命令路由。

HA / Ego / Superego

HA 理解和验收，Ego 执行，Superego 评审和审计。

默认低熵自主闭环
Run Evidence

测试、typecheck、lint、schema、diff、审批和用户反馈。

LowEntropySignal

带来源、hash、可信度、时效、脱敏和保留策略的证据。

EntropyLedger

记录 evidence、risk、uncertainty、informationGain 和门禁。

↓
Experience Graph

串联 task、trace、result、experience、reflection 和 dream。

AutonomyJob

统一调度 reflection、dream、prune、consolidation。

Safety Gates

权限、预算、审计、secret scan、边界 diff 和用户抢占。

↓
MemoryArtifact

可检索经验、风险、模式、规则候选和测试候选。

Consolidation

多次验证后晋升为 eval、policy、skill、doc、validator。

Prompt Augmentation

反向增强后续 HA、Ego、Superego 的判断和执行。

可选 Goal 控制面
Goal / Subgoal

记录长期方向、边界、预算、验收条件和暂停/恢复状态。

GoalController

管理命令语义、状态机、续跑 prompt 和权限上下文摘要。

GoalJudge

只在有 Goal 时判断 done、continue、pause、blocked、expire。

goal_continuation

作为 AutonomyJob 的一种类型进入统一 scheduler。

默认闭环：没有 Goal 也运行 Goal：只增加人的可控性 副作用操作：始终走权限和审计 Dream：只改 Experience Graph

二、分层职责

协议和用户控制层

AionUI、ACP Server 和 CLI 负责接收任务、展示状态、处理权限请求和路由 Goal 命令。

  • 不直接改写业务状态。
  • 不推断 Goal 结论。
  • 不绕过权限策略。

执行和评审层

HA / Ego / Superego 完成单轮任务闭环，产出验收合同、执行结果、审计评审和返工建议。

  • Ego 负责执行和验证。
  • Superego 读取 AuditPacket。
  • HA 面向用户汇报。

低熵证据层

LowEntropySignal 和 EntropyLedger 把分散的验证、审计、反馈变成可计算、可追溯的证据账本。

  • 信号带 source、hash、TTL。
  • secret 阻塞长期保存。
  • 硬门禁优先于分数。

自主调度层

Autonomy Scheduler 使用 SQLite lease claim 到期任务，统一处理 reflection、dream、prune、consolidation 和 goal_continuation。

  • 跨会话单实例运行。
  • 崩溃后 lease 过期接管。
  • 用户消息可抢占。

经验和记忆层

Experience Graph 串联任务、过程、结果、反思、梦境和候选改进，MemoryArtifact 提供检索入口。

  • 经验不是事实源。
  • 高置信经验才能晋升。
  • Dream 可裁剪低价值节点。

Goal 控制层

GoalController 和 GoalJudge 只在用户设置 Goal 后启用，用来增加方向、边界、预算和可暂停控制。

  • Goal 不证明任务完成。
  • Goal 不继承长期审批。
  • Goal 不影响无 Goal 改进闭环。

三、关键运行路径

无 Goal 的默认自主改进

  • 用户发起普通任务，HA / Ego / Superego 完成单轮闭环。
  • 系统收集验证、审批、审计和反馈，生成 LowEntropySignal。
  • EntropyLedger 记录证据质量和剩余不确定性。
  • Experience Graph 写入 task、result、experience 和信号关联。
  • Scheduler 到期 claim reflection / dream / consolidation。
  • 多次验证的经验晋升为 eval、policy、skill、doc 或 validator candidate。

有 Goal 的受控长任务

  • 用户创建 Goal，声明长期意图、边界、预算和验收条件。
  • Goal 关联普通 run 产生的低熵信号，但不取代证据。
  • Scheduler 额外 claim `goal_continuation` job。
  • GoalJudge 基于信号、预算、审计和权限上下文判断下一状态。
  • 用户可以随时 pause、resume、clear 或追加 Subgoal。
  • 无 ACP permission channel 时，副作用 continuation 必须暂停。

四、安全和收敛矩阵

证据收敛

测试、typecheck、schema、AuditPacket、用户反馈和脱敏样本形成低熵信号，减少模型自信幻觉。

权限约束

读操作可自动；写文件、编辑文件和执行命令必须经过当前会话或 daemon 策略授权并写审计。

预算控制

每个 AutonomyJob 受 depth、wakeups、children、time 和 risk budget 控制，避免无限反思。

扰动边界

ContextPerturbation 只能作为候选上下文注入，不能覆盖系统规则、验收合同、权限或事实门禁。

五、最终状态

MAS 自己会越来越稳

即使用户从不设置 Goal，系统也会从每次任务中抽取验证、风险、失败模式和改进候选，让后续 HA / Ego / Superego 更会判断、更会执行、更会验收。

人可以随时接管方向

当用户设置 Goal，MAS 不会突然获得新权限，而是获得明确目标、边界、预算和暂停/恢复控制。Goal 是可控性增强，不是自主性来源。
