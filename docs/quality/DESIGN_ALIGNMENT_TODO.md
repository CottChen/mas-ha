## 信息与证据

- [讨论] 设计基于独立性、相关性、重复度、来源可靠性、可证伪性和时效性的证据模型，禁止用信号条数直接代表信息量。
- [ ] 保存评分所依据的原始信号、公式版本、权重、解释和重算结果，支持离线回放与校准。
- [ ] 区分系统计算、Agent 自报和用户反馈；Agent 的 `evidenceQuality`、`entropyDelta` 不能直接覆盖系统证据。
- [ ] 对重复 validator、同源派生事件和相关 audit finding 去重或降权，避免重复信息抬高 evidence score。
- [ ] 使用真实历史任务建立校准集，检验 uncertainty、evidence quality 和 information gain 对最终验收与用户纠正的预测能力。

## 混沌与受控扰动

- [讨论] 为至少两个独立视角提供异质外部取证：可以是 Ego/Superego 的受限工具，也可以是可审计 Researcher 委托；不能只依赖 HA 初始和终验两次检索。

## 真实任务验证

以下是所有上述代码或 Prompt 修改完成后的共同完成条件，不满足时 TODO 不能关闭：

- [ ] 固定旧版和新版的 commit、Prompt 版本、模型、thinking level、工具集、权限模式、输入 fixture 和随机 seed。
- [ ] 同一任务至少运行旧版和新版对照；模型有明显随机性时每版重复运行，不能选择性保留成功样本。
- [ ] 保存完整 Agent 结构化输出、工具与证据记录、AuditPacket、最终用户结果、耗时和 token/调用成本。
- [ ] 使用外部事实的任务必须读取原始来源并检查 faithfulness；只拿搜索摘要不算通过。
- [ ] 失败恢复任务必须证明新版改变了控制动作；重复同一 Prompt 后偶然成功不算反馈改进。
- [ ] Prompt 改动必须至少覆盖相关角色的真实 Pi run；字符串包含断言和模型自评只能作为结构检查。
- [ ] 结果由确定性 validator、人工盲评或用户反馈判定，不能由被测 Agent 自己批准。

最小真实任务集：

| 场景 | 主要检验 |
| --- | --- |
| 本地代码缺陷 | Ego 现实检验、最小修改、验证和审计 |
| 依赖最新第三方文档的任务 | 知识缺口、自适应检索、原文忠实度 |
| 两个来源存在冲突的事实任务 | 异质证据、分歧保留和 Judge 裁决 |
| 高风险结构化数据任务 | 口径、抽样复算、证据独立性和失败披露 |
| 连续两轮同类失败 | 控制动作是否换路并真正降低不确定性 |
| 权限、凭据或不可逆风险 | 正确升级用户，避免盲目自主或无效打扰 |
| 重复模式和扰动任务 | 固定模式识别、扰动生命周期和结果归因 |

共同指标至少包括：真实完成率、关键验收通过率、外部证据忠实度、回答相关性、返工收敛轮次、无效用户升级率、越权/安全事件、无关改动率、实际异质性和平均成本。
